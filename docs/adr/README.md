# Architecture Decision Records

Значимые архитектурные решения по проекту: почему выбрали так, что рассматривали и от чего отказались.

ADR пишется на решение, которое дорого откатывать и о котором через полгода спросят «почему так?»: выбор технологии, схема аутентификации, контракт между сервисами, отказ от целого подхода. Не пишется на багфиксы, обновления версий и детали реализации — их место в git-истории и комментариях в коде.

Принятый ADR не переписывают. Если решение отменили — заводится новый, со статусом `Supersedes NNNN`, а у старого статус меняется на `Заменён`. История ошибок ценна ровно так же, как история удач.

## Статусы

- **Предложено** — обсуждается, решение не принято.
- **Принято** — решение действует, по нему живём.
- **Заменён** — отменён другим ADR, ссылка на него в тексте.
- **Отклонено** — рассматривали и не приняли; запись оставлена, чтобы не возвращаться к вопросу с нуля.
