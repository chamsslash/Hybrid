# Обновление документации проекта — дизайн

Дата: 2026-07-22
Рабочая ветка: `feat/minio-image-pipeline`
Эпик: `Hybrid-kubernetes-non-local-csd` (RESCUE)

## Проблема

За сессию сделан большой объём изменений (миграция auth на SPA-модель, MinIO-пайплайн картинок, чистка мёртвого кода, харденинг CI/секретов), а документация проекта не поспевает:

- `docs/` почти пуст — только `refresh-flow.md` (частично обновлён по ходу сессии) и два design-спека этой же сессии.
- `README.md` частично свежий (T3 обновлял по секретам/`.env`), но ни слова про MinIO/картинки.
- `AGENTS.md` (репо-гайд) существенно устарел: ссылается на несуществующий сервис `JwtProxy/`, несуществующие `nginx/`, `scripts/`, `docker-compose.local.yml`; утверждает «тестов нет», хотя их 30+ (unit + Testcontainers).
- Нет ни одного документа архитектурного/сервисного уровня — только код и разрозненные design-спеки конкретных фич.

## Аудитория и объём

- **Аудитория:** сам автор проекта, возвращающийся через недели/месяцы. Не онбординг незнакомца — фокус на архитектурных решениях и причинах «почему так», а не на объясняющем тоне для новичка.
- **Временной охват:** только текущее состояние системы, без чейнджлога/истории изменений этой сессии — историю правок хранит `git log`, дублировать её в докax не нужно (иначе доки устаревают при первой же следующей правке).
- **Глубина:** архитектурный/сервисный уровень. Не построчное описание кода — методы и классы упоминаются только там, где это ключевая точка входа (например, эндпоинт, топик Kafka, контракт), а не полный листинг.

## Решения

- **Структура:** по-сервисные доки + общий обзор (не один большой ARCHITECTURE.md, не только точечные правки существующих файлов).
- **`docs/refresh-flow.md` → `docs/security-flow.md`** (переименование, контент уже актуален — обновлялся в ходе сессии под STOMP-auth).
- **`.claude/`** добавлен в `.gitignore`, `CLAUDE.md` подчищен от задублированного глобальным конфигом правила — сделано отдельным коммитом до этого спека, к текущей задаче не относится содержательно, упомянуто для целостности сессии.
- **`AGENTS.md`** остаётся вне git (подтверждено пользователем как осознанное решение) — чинится локально, без коммита; не часть публикуемой документации.

## Содержание по файлам

### `docs/OVERVIEW.md`
- Что такое система (мессенджер), список сервисов с одной строкой ответственности каждого (AuthService, HTTPService, MessegerParody, Helm/инфра: Kafka, Postgres, Redis, MinIO, Prometheus/Grafana).
- Топология деплоя: k8s/Helm/kind; явно зафиксировать, что режима docker-compose больше нет.
- Верхнеуровневые потоки данных:
  - auth-flow — кратко (OAuth → access-in-memory → refresh-cookie → `/api/*` Bearer), глубина в `security-flow.md`.
  - message-flow — топики Kafka (`Messages`, `Images`, `Events`) и кто producer/consumer.
  - image-flow — upload → MinIO → Kafka `Images`-контракт → два независимых консюмера (персист + live-STOMP) → `/api/images/{key}`.
- Стек: WebFlux+MVC микс в HTTPService, gRPC между сервисами (`ReactiveTransferService`, `AuthTransferService`), Kafka, Postgres+Liquibase, Redis (fingerprint/refresh-сессии), MinIO.
- Ссылки на все остальные доки в `docs/`.

### `docs/AuthService.md`
- Зона ответственности: OAuth-логин через Google, выдача первичной пары токенов, эндпоинт `/jwtcheck`, который вызывает ingress `auth_request` для валидации access-токена.
- Ключевые компоненты (кратко, без построчного разбора).
- Конфиг/секреты, которые нужны сервису.
- Как запускать и тестировать локально.

### `docs/HTTPService.md`
- SPA-auth: access-токен только в памяти браузера, refresh — HttpOnly cookie; `/api/*` защищены `Authorization: Bearer`; STOMP CONNECT аутентифицируется access-токеном отдельно (SockJS-хендшейк не несёт заголовков) — краткое изложение, детали в `security-flow.md`.
- MinIO-пайплайн картинок: `Upload_image(file, targetId, targetType)` → `MinioClient.putObject` → публикация контракта `{targetType, targetId, objectKey}` в топик `Images`; отдача через `GET /api/images/{key}` (прокси, стриминг из MinIO).
- AI-ассист (Yandex GPT): `/AiAssist` → `YandexGptService`; статус фичи (рабочая, но есть известные недоделки) со ссылкой на beads-задачу `ebo`.
- Роли Kafka producer/consumer в этом сервисе (в т.ч. форвард image-событий в STOMP для live-обновления).

### `docs/MessegerParody.md`
- Зона ответственности: владелец БД (JPA для блокирующих операций + R2DBC для реактивных), gRPC `ReactiveTransferService`, Kafka-консюмер (`Images` → `ImageUrlPersistenceService`, `Events`).
- Liquibase-миграции (включая нормализацию legacy `image_url`).
- Явный список удалённого мёртвого кода (`MTS_impl`, `gRPC_Client`, `GoogleDriveProvider`/`GoogleDriveService`, legacy `JWT_Service`) — чтобы не искали в будущем несуществующее.

### `docs/security-flow.md`
Переименование `refresh-flow.md` без содержательных изменений — файл уже обновлялся в ходе сессии (SPA access-in-memory, STOMP-auth раздел). Обновить входящие ссылки на него (`README.md`, новый `OVERVIEW.md`).

### `README.md`
- В список «Что внутри» добавить MinIO.
- Короткий абзац-указатель на `docs/OVERVIEW.md` как точку входа в архитектуру.

### `AGENTS.md` (локально, без коммита)
- Убрать упоминания `JwtProxy/`, `nginx/`, `scripts/`, `docker-compose.local.yml` (не существуют в репозитории).
- Поправить раздел «Тестирование»: тесты есть (unit + Testcontainers), обязательно упомянуть JDK21-требование (JDK25 ломает Mockito).
- Обновить список реальных top-level директорий (`AuthService/`, `HTTPService/`, `MessegerParody/`, `Helm/`, `docs/`).

## Валидация фактов (важно после урока с AGENTS.md)

Каждый факт в новых доках проверяется по актуальному коду/конфигу перед записью (grep/чтение файла), а не по памяти о том, что «должно быть». Это то же самое требование, которое подвело `AGENTS.md` в прошлом — документация о несуществующем сервисе `JwtProxy` пролежала незамеченной.

## Не-цели

- Чейнджлог/история изменений этой сессии — не пишем (см. «Аудитория и объём»).
- Построчные комментарии к коду.
- Обновление `AGENTS.md` в git — он намеренно вне трекинга.

## Реализация

Все 5 файлов `docs/*` + `README.md` — независимы по файлам. Реализация через декомпозицию в beads на самодостаточные подзадачи (по одной на файл), с раздачей сабагентам на Sonnet, каждая — в своей ветке, интеграция в `feat/minio-image-pipeline` по готовности. `AGENTS.md` правится инлайн, без отдельной ветки/коммита.
